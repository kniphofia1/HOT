# ADR 0001：MVP v0.1 范围决策

## 状态

Accepted

## 背景

本项目的产品方向是“研究员情报雷达”：收集可信来源，保留原始证据，把相关内容聚类为事件，解释事件为什么重要，并导出 Markdown 简报。

长期产品可以扩展到更多社交平台、国内平台、高级导出、多租户客户门户、评论分析和通知工作流。但如果 v0.1 就实现这些能力，首版会过宽，容易变成一个浅层信息聚合工具，而不是可靠的研究工作流。

v0.1 的关键验证点不是平台数量，而是系统能否把少量可靠来源转化为可追溯、可聚类、可写入简报的情报。

## 决策

v0.1 只实现：

- RSS
- 公开网页监控，支持 CSS Selector 文本抽取
- Hacker News
- GitHub repo watch
- GitHub release watch
- AI 聚类与摘要
- `Evidence` 来源引用
- 可解释 `hotScore`
- Markdown 简报导出
- 本地单机部署

v0.1 不实现：

- 国内平台
- X / Twitter 真实数据 `Connector`
- PDF 导出
- Word / DOCX 导出
- YouTube 真实抓取
- 评论抽样
- 全量评论情感分析
- 多租户
- 登录态抓取
- Cookie 抓取
- 验证码处理
- 私有网页抓取

YouTube 在 v0.1 中只能作为 `Connector` placeholder 或接口占位存在，用于保留后续扩展点。它不得执行真实 API 请求或真实网页抓取。

## 理由

### 国内平台延后

微博、B站、知乎、微信公众号、小红书、抖音、快手等平台的数据权限、API 可用性、账号要求、审核流程、风控规则和内容结构差异很大。

如果 v0.1 纳入这些平台，连接器工作会主导整个版本，反而削弱更重要的验证目标：可信来源链路、聚类质量和简报输出。

v0.1 的正确做法是保留可扩展 `Connector` 架构，但不交付国内平台连接器。

### X / Twitter 延后

X 数据访问成本高，政策变化也较频繁。把 X 作为 v0.1 默认来源会带来预算、可靠性和产品范围风险。

X 应该在后续作为可选付费 `Connector` 添加，并且需要明确成本、限流、错误降级和合规边界。

### PDF 和 Word 延后

Markdown 是验证简报质量最快的形式。PDF 和 Word 会提前引入排版、样式、模板、渲染和兼容性复杂度。

v0.1 应先证明被选中的事件、摘要、引用和人工点评能组成有用的简报。等 Markdown 简报质量稳定后，再叠加 PDF 和 Word。

### YouTube 真实抓取延后

YouTube 有价值，但真实接入需要处理 API 配额、凭证、频道/关键词建模、视频元数据和额外指标。

v0.1 只保留 YouTube placeholder。这样既能保持架构开放，又不会增加首版实现风险。

## 影响

正面影响：

- v0.1 足够小，可以严谨实现和测试。
- 系统优先验证 `RawItem`、`Evidence`、`EventCluster`、`hotScore` 和 Markdown 简报质量。
- `Connector` 架构可以先在稳定来源上验证，再扩展困难平台。
- 合规风险更低，因为范围只包含官方 API、公开 API、RSS 和公开网页。

负面影响：

- v0.1 覆盖平台少于长期愿景。
- v0.1 不覆盖国内社交趋势或 X 讨论场。
- PDF / Word 客户交付格式必须等后续版本。
- YouTube 监控必须等后续版本。

## 后续扩展条件

在满足以下条件前，不得添加被延后的平台或导出格式：

- Milestone 1-5 完成
- Markdown 简报已经能用于真实评审
- RSS、网页、HN、GitHub 来源上的聚类质量可接受
- `Evidence` 引用链路可靠
- `Connector` 健康状态和失败日志可见
- 新平台具备清晰 API、成本、限流和合规方案
